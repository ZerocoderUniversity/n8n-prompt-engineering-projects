# PEn05. ИИ-ассистент обработки клиентских заявок

## Зачем этот проект

Проект превращает набор знакомых нод в рабочий MVP поддержки. Он показывает, как использовать LLM для понимания текста, сохраняя критичные бизнес-решения за детерминированными правилами и человеком.

## Что делает workflow

1. Принимает заявку через Webhook.
2. Проверяет имя, контакт и текст, нормализует вход и создаёт `ticket_id`.
3. Не пропускает невалидную заявку к платной модели.
4. Передаёт текст ИИ-агенту на базе YandexGPT.
5. Получает структурированный JSON: категорию, приоритет, краткое резюме, недостающие данные и черновик ответа.
6. Применяет бизнес-правила, включая повышение приоритета при критичных признаках.
7. Сохраняет заявку и черновик в NocoDB.
8. Уведомляет ответственного в Telegram и возвращает ответ webhook-клиенту.

## Почему архитектура устроена так

Модель классифицирует и предлагает текст, но не отправляет ответ клиенту и не принимает необратимых решений. Валидация, эскалация приоритета и защита от prompt injection дублируются в коде, поэтому поведение не зависит только от ответа LLM.

## Что настроить после импорта

- Webhook и тестовый запрос;
- YandexGPT через OpenAI-совместимый Base URL;
- NocoDB и таблицу для заявок;
- Telegram Credentials и получателя уведомлений;
- допустимые категории и бизнес-правила.

## Файлы

- `workflow.json` — готовый workflow;
- `materials/lesson.pdf` — презентация с архитектурой и объяснением проекта.

## Проверка

Прогоните минимум три сценария: корректную заявку, заявку без обязательного поля и текст с попыткой подменить инструкции. Убедитесь, что клиенту автоматически ничего не отправляется.

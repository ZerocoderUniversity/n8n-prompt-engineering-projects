# PEn06. Надёжная обработка заказов

## Зачем этот проект

Рабочий прототип недостаточно просто запустить один раз. Этот workflow показывает, как подготовить ИИ-автоматизацию к сбоям внешних сервисов, повторным webhook-запросам, неверному ответу модели и контролю расходов.

## Что делает workflow

1. Принимает заказ через Webhook.
2. Загружает настройки и проверяет лимиты.
3. Валидирует вход до платного вызова модели.
4. Проверяет дубли по idempotency key или данным заказа.
5. Создаёт запись со статусом `processing`.
6. Передаёт заказ ИИ-агенту с YandexGPT и проверяет структурированный ответ.
7. Обновляет заказ статусом `done`, `needs_review` или `failed`.
8. Пишет технический журнал без персональных данных.
9. Отправляет алерт в Telegram при проблеме и возвращает понятный ответ клиенту.

## Ключевые идеи

- проверка дубля выполняется до вызова LLM;
- запись создаётся до рискованного шага и обновляется после него;
- повторный запуск опирается на сохранённый `retry_payload`;
- ожидаемые ошибки обрабатывает ветка workflow, неожиданные — отдельный Error Workflow инстанса;
- статусы служат инструкцией оператору;
- мягкий выключатель позволяет остановить обработку без доступа к n8n.

## Что настроить после импорта

- YandexGPT Credentials и таймаут;
- NocoDB: таблицы заказов, настроек и журнала;
- Telegram для аварийных уведомлений;
- лимиты стоимости и количества заказов;
- сохранение прогресса выполнения и Error Workflow в настройках n8n.

## Файлы

- `workflow.json` — надёжная версия сценария обработки заказов;
- `materials/lesson.pdf` — карта отказов, настройки и инструкция по восстановлению.

## Проверка

Проверьте валидный заказ, повтор одного запроса, недоступность LLM, неверный формат ответа и выключенную обработку. В каждом случае должны остаться понятный статус, запись в журнале и безопасный ответ.

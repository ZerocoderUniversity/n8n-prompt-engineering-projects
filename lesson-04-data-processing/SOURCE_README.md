# Материалы к уроку PEn04: n8n, часть 2

## Состав комплекта

- `01-data-transformation.json` — Edit Fields, Code и Date & Time.
- `02-cleaning-and-aggregation.json` — Remove Duplicates, Sort, Limit и итоговая агрегация.
- `03-if-and-merge-shipments.json` — три отправления, IF, две инструкции и повторный Merge.
- `04-switch-routing.json` — маршрутизация London / New York / Tokyo / Other через Switch.
- `05-arrays-loops-filter.json` — восемь клиентов, Split Out, Loop Over Items по два, Filter, Switch, Merge и итоговая статистика.
- `06-error-handling-demo.json` — безопасная демонстрация Retry On Fail и отдельного Error Output без внешнего API.
- `clients-example.json` — исходные данные для самостоятельной практики.

## Как импортировать workflow

1. Откройте n8n.
2. В меню workflow выберите **Import from File**.
3. Выберите нужный `.json`-файл.
4. Нажмите **Execute Workflow** и просмотрите данные после каждой ноды.

Все сценарии используют Manual Trigger и тестовые данные, поэтому Credentials не требуются. Если ваша версия n8n предлагает обновить версию ноды после импорта, согласитесь и проверьте параметры ноды перед запуском.

## Порядок прохождения

1. Импортируйте файлы 01–04 по мере просмотра соответствующих разделов.
2. Перед разделом о массивах откройте `clients-example.json` и сравните один объект с массивом объектов.
3. Импортируйте файл 05, поставьте breakpoint после Split Out и выполните сценарий по шагам.
4. Для самостоятельной работы измените города, статусы и пустые телефоны, затем сравните итоговую статистику.
5. Импортируйте файл 06 и проследите, как тестовая ошибка уходит на отдельный выход после трёх попыток.

## Проверка результата

- После Split Out должно быть 8 items.
- Loop Over Items выдаёт элементы пакетами по 2.
- Два клиента без телефона попадают в категорию `skipped`.
- Клиенты со статусами `new` и `active` получают разные сообщения.
- `blocked` и `unknown` идут в запасную ветку `other`.
- Итоговая нода возвращает счётчики категорий.

## Credentials, Test/Production и ошибки

- Не вставляйте токены и пароли прямо в поля нод: используйте Credentials.
- Проверяйте workflow в ручном режиме до активации production-триггера.
- Для сетевой ноды включайте Retry On Fail только для временных ошибок.
- Для поэлементной обработки выбирайте Error Output или Continue Using Error Output, чтобы один неудачный item не останавливал весь поток.
